# AI 简历填表助手

基于 Chrome / Edge Side Panel 的浏览器扩展。维护 Markdown 个人资料，AI 读取网页表单需求后生成填写内容，再由本地脚本校验和操作控件。默认不自动提交。

## 工作方式

1. 在插件内维护一份或多份 Markdown 资料，章节、字段和内容不限。
2. 点击填写后，扫描当前页面或选区的字段标签、区块、选项及原生输入约束。
3. 将当前资料和表单字段发送到你配置的 OpenAI 兼容模型接口。
4. AI 为每个页面字段返回实际填写值、资料引用和处理状态，不再选择预设简历字段路径。
5. 本地校验答案及当前控件，再填入网页。侧边栏展示填写结果，提交仍由你完成。

例如，在 Markdown 中新增“常玩的游戏：星际争霸”或“导师：王老师”，遇到对应问题时即可使用，无需修改字段库或代码。

## 信息缺失时如何处理

| 情况 | 行为 |
| --- | --- |
| 资料明确记载 | 提取或转换格式后填写 |
| 有明确依据可计算或转换 | 根据资料推导，保留引用供检查 |
| 自我评价、项目描述等描述题 | 根据已有资料撰写，标记“AI 生成 · 请检查” |
| 缺失客观事实或个人意愿 | 保持原控件内容，显示“待补充” |
| 资料矛盾、答案不符合控件约束 | 显示待补充或需核对原因 |
| 控件操作失败 | 显示“填写失败”，其余字段继续处理 |

没有提及某段经历不等于没有经历。缺失的证件号码、学历、成绩、薪资期望、到岗时间等不能凭空补齐。资料引用和本地检查能帮助发现错误，但不能证明所有语义判断都正确，请在提交前检查。

补充资料后保存，再点击“增量填入”，继续填写空项。AI 生成内容只用于本次表单，不会自动写回 Markdown。

## 资料管理

- 侧边栏“个人资料”可直接编辑，也可打开宽页面编辑器。
- 支持多份资料的新建、复制、重命名、删除和切换。
- 单份资料支持 `.md` / `.markdown` / `.txt` 导入、`.md` 导出。
- 全部资料使用 JSON 备份和导入；仍可导入旧版简历 JSON。
- PDF 导入直接追加原始文字，不经过固定字段抽取。扫描版 PDF 需要先 OCR。
- “插入参考章节”提供可选提纲，不限制内容格式。
- 修改后点击“保存资料”；填写、切换、复制和导出前也会保存当前修改。
- 编辑器有未保存内容时，其他窗口的变更不会直接覆盖编辑区，会提示核对。

资料示例：

```markdown
# 个人资料

## 基本信息
- 姓名：张三
- 邮箱：zhangsan@example.com

## 项目经历
### 浏览器填表助手
使用 JavaScript 开发表单扫描和控件填写功能，负责需求分析与实现。

## 求职偏好
- 目标岗位：前端开发
- 期望城市：上海

## 其他信息
- 导师：王老师
- 常玩的游戏：星际争霸
```

只填写真实信息；未确定的偏好可暂不填写。

## 旧版本升级

首次打开侧边栏或编辑器时，会把原有多份简历转换为 Markdown，保留名称和当前选择。结构化字段、未知字段及全部经历条目都会保留；历史导入原文单独放在“待核对”章节。

旧数据会先备份到本地的 `resumeMarkdownMigrationBackupV1`，新资料写入成功后才清理旧存储键。可点击“导出迁移前备份”下载原始数据；该文件也可通过全部资料的“导入”重新转换。请检查新旧信息有无冲突，然后整理文档。

新的长期资料存储只有 Markdown 和资料名称、ID、时间等元数据。旧字段库不再参与填写；`shared/resume-schema.js` 仅供旧资料迁移和兼容测试使用。

## 安装与模型配置

1. 打开 `chrome://extensions/` 或 `edge://extensions/`，开启开发者模式。
2. 点击“加载已解压的扩展程序”，选择项目目录。项目无需构建。
3. 点击扩展图标打开侧边栏，在右上角设置模型。
4. 填写资料并保存，切换到目标网页执行填写。

支持 `POST /chat/completions` 的 OpenAI 兼容接口，例如：

- Base URL：`https://api.deepseek.com/v1`
- Model：`deepseek-chat`
- API Key：你自己的 Key

模型配置与 Key 均保存在当前浏览器的本地扩展存储，不通过 Chrome Sync 同步，也不传给页面脚本。接口默认要求 HTTPS，允许本机 HTTP 调试地址。

升级后请重新加载扩展，并刷新已经打开的表单页，避免继续使用旧页面脚本。

## 填写模式与支持范围

- **开始填充**：填写本次识别到的可用字段，可能覆盖已有内容。
- **增量填入**：跳过已有内容；模型请求返回后再次检查，保护等待期间的手动输入。
- **选区填入**：拖拽框选网页区域，仅扫描和填写该区域。

支持文本框、文本域、下拉框、单选组、多选组、`contenteditable` 和部分只读日期控件。整页填写会尝试展开明确的已有折叠区块，不会点击新增、删除或提交按钮；选区模式不自动展开区块。

会读取原生的必填、长度、范围、步长和格式约束。选择题必须使用扫描到的完整选项文字，写入前再次检查选项是否仍然可用。

限制：

- 不自动提交，不自动上传文件。
- 跨域 iframe、复杂自定义控件和分步动态页面可能需要手动操作或站点适配。
- AI 仍可能判断错误；资料缺失、语义不明确或格式无法满足时可能留空。
- 单份资料超过 10 万字符时会明确报错，不会静默截断；模型本身的上下文限制仍可能更小。
- 每次填写重新生成答案，不缓存旧的填写值。调用耗时和费用取决于资料长度、字段数量及模型。
- “清理旧版缓存”仅删除旧版本字段映射缓存。

## 隐私与诊断

Markdown、迁移备份和模型配置都保存在 `chrome.storage.local`。填写时，当前 Markdown、表单标签、选项、上下文及页面信息会发往配置的模型接口；页面 URL 会移除 query/hash。

侧边栏的本次填写报告包含答案、原因和引用，供你检查，不持久化为资料。新的填写诊断只记录字段 ID、来源、处理状态及统计，不将答案和引用写入诊断日志。配置项目目录后，诊断日志仍可导出到 `debug-logs/`。

## 开发与验证

```bash
npm test
```

使用 Node 内置测试运行器，覆盖 Markdown 资料迁移与备份、多资料管理、并发存储、答案校验、缺失事实处理、增量和选区流程、页面字段扫描辅助函数及模型配置。

主模块：

- `shared/resume-storage.js`：Markdown 资料存储、旧数据迁移、备份与多资料操作。
- `shared/document-editor.js`：侧边栏和独立页面共用的资料编辑器。
- `shared/form-plan.js`：AI 规则、请求构造、JSON 解析及答案校验。
- `background.js`：读取模型配置并代理模型请求。
- `content.js`：网页扫描、原生约束检查及控件写入。
- `popup.js`：填写入口、状态与结果报告。

仓库保留的 `modules/`、`templates/` 是早期问卷模板实验模块，不是 Markdown 填表主流程。
